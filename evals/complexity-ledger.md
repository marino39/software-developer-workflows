# Complexity ledger

Every non-obvious construct in the workflow costs tokens, latency, and reader
attention. This ledger is the **complexity budget**: each accreted construct must
name the concrete failure it prevents and where that justification comes from.
Rows sourced to `intuition — unverified` are the standing simplification backlog —
they get an ablation variant and a live A/B (`/workflow-eval --variant`) before we
either keep them on evidence or cut them.

The lint (`evals/lint.sh` Check 6) enforces that every row has a **Prevents** and a
**Source**; it does not (cannot) enforce that every construct is listed —
completeness is a review discipline (see `CLAUDE.md`).

**2026-09-07 model-tuning pass (Anthropic Opus 5 / Fable 5.1 guidance;
`docs/proposals/2026-09-07-opus5-fable51-model-tuning.md`).** Four changes applied: a
**delegation cap** added beside the existing floor (Opus 5 delegates more readily than the
model the floor was measured against — the floor stops under-delegation, the cap stops
over-delegation); `architect`/`debugger` effort `xhigh`→`high` (the vendor default; a
parameter, not a construct — no row, restore variant `agent-effort-xhigh-restore`, and the
validation is owed in a **real CLI run** because effort is inert in this harness); the
`reviewer` stops pre-filtering on severity and reports a per-finding confidence (vendor
guidance: severity filters depress measured recall — filtering already lives in the Phase 6
consolidation pass); and a **Model-tuning notes** section recording that the fleet is
heterogeneous under one set of prompts, so model-specific guidance applies per file by the
model that reads it. Unlike the 2026-08-11 passes this one is **vendor-guidance-sourced**,
which is evidence about the models, not about this suite — so every row below still names
its A/B. Two findings were deliberately **not** applied and are queued as backlog:
`verify-scaffold-trim` (Opus 5 says delete verification instructions; Fable 5.1 says keep
them, and the ladder can put Fable in those seats) and a re-A/B of the delegation floor
itself, whose 2026-07-22 evidence predates the model whose default it corrects.

**2026-09-07 cross-vendor allocation pass (user directive "Apply" on
`docs/proposals/2026-09-07-codex-astra-model-allocation.md`).** Codex stopped being one
free, unbounded thing: the CLI now picks between four models (its bundled default moved
to the flagship, silently re-pricing every codex pass in the workflow) and a plan-billed
CLI meters the flagship per 5-hour window, while an API-billed one costs more per cached
token than any model in the Claude fleet. Four constructs added below — a codex ladder +
one-flagship-per-run budget, a codex root-cause rung ahead of the one fable escalation,
a batched out-of-model claim verification replacing address-review's per-item fan-out,
and a review remit led by comparative advantage instead of duplicating the bug scan.
Three text corrections carry no row because they add no construct: pinning `--model`
(determinism), a quota exit class with a tier downshift (`codex-exec` §3, previously an
untyped "other nonzero" skip), and the removal of the "codex is free" claim. Like the
2026-08-11 pass this is **directive-sourced, not evidence-sourced on this suite** — the
vendor and third-party numbers are evidence about the **models** — so every row names
its owed A/B, and all four variants are authored.

**Status legend:** `keep` = justified, not currently questioned · `ablation-queued`
= has a variant, awaiting an A/B · `candidate` = flagged, no variant authored yet ·
`consolidated` = simplified in place without behavior change.

layer goes, so each cut row names its restore variant and carries an explicit OWED. The
honest status of this pass is: cost saving certain, quality delta unmeasured.
